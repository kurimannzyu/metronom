# Blue Tempo 試用版

スマートフォン用のメトロノーム。外部ライブラリ・ビルド不要のHTML / CSS / JavaScriptです。

## まず試す
1. 案内された試用URLをiPhoneのSafariで開きます。非公開Sitesの場合は作成者のアカウントでサインインしてください。
2. STARTを押し、本体の音量を上げます。初回は音声の開始にタップ操作が必要です。
3. 重りを上にドラッグすると遅く、下にドラッグすると速くなります。再生中も音は継続し、ドラッグ中だけ棒が中央で固定されます。−／＋でテンポを変更します。長押しもできます。数字をタップして直接入力後、キーボードの完了を押します。
4. 拍子を選びます。拍子・分割を変更すると停止するのでSTARTを押します。BPMは再生中にも変更できます。
5. TAPを数回押すと、その間隔からBPMを設定します。
6. 「音とリズムの設定」でアクセント・細分化・音量を調整します。「音 ON」でミュートを切り替えます。
7. Safariの共有 → ホーム画面に追加 → 追加。そのアイコンから起動します。

AndroidではChromeのメニュー → ホーム画面に追加を使います。設定は端末・ブラウザ・URLごとに保存します。Safariとホーム画面版で設定が別になる場合があります。

## GitHubに保存して公開（初心者向け）
1. GitHubにアカウントを作成し、ログインします。
2. 右上の「＋」→「New repository」を選び、名前を `blue-tempo` にします。
3. Publicを選択し「Create repository」。公開コードになるため個人情報は入れないでください。
4. 「uploading an existing file」または「Add file → Upload files」を選びます。
5. このフォルダの **distの中身** をアップロードします。distフォルダ自体でなく、index.html、app.js、style.css、manifest.webmanifest、sw.js、iconsフォルダを選んでください。README.mdも追加できます。`.openai`や`.git`は不要です。
6. 「Commit changes」を押して保存します。
7. リポジトリの Settings → Pages → Sourceを「Deploy from a branch」にします。
8. Branchを `main`、フォルダを `/ (root)` にしてSave。
9. 数分待ち、Pagesに表示されたHTTPSのURLをSafariで開きます。
10. そのURLをホーム画面に追加します。以降はGitHub上でファイルを更新しCommitすると再公開されます。

GitHub手順の公式資料：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## ローカルで確認する場合
Macのターミナルで `cd ` と入力後、distフォルダをドラッグしReturn。続いて `python3 -m http.server 8080` を実行し、Macのブラウザで http://localhost:8080 を開きます。終了はControl+C。同じWi-FiのiPhoneからMacのLAN IPで画面は確認できますが、HTTPのLAN接続ではPWAのService Workerは使えません。ホーム画面・オフライン確認にはHTTPSの公開URLを使ってください。

## 動作範囲と確認
- Web Audioの時計を使い、25msごとに100ms先までクリックを予約します。BPM変更は予約済みの音の後に反映されます。
- 振り子と拍表示は音声時刻から描画。画面更新頻度やBluetooth機器の遅延で見た目とのずれが出る場合があります。
- 6/8のBPMは8分音符単位。6クリックで1小節です。
- 音声ファイルの自動再生に依存せず、STARTのユーザー操作でAudioContextを作成・再開します。
- **通常再生**：画面を表示して使用します。対応ブラウザでは画面が眠らないようWake Lockを要求しますが、許可やOS状態で使えない場合があります。
- **ロック中・別アプリ中**：本試用版では対応しません。画面が非表示になると明示的に停止します。iOSのWeb Audioには中断・背景動作の制約があり、PWA化だけでは解消しません。戻ってSTARTを押してください。
- 初回アクセス後にService Workerが必要ファイルを保存します。オフライン対応はHTTPSまたはlocalhostで有効です。非公開Sitesの認証や端末によるキャッシュ削除により再通信が必要になることがあります。長期利用はGitHub Pagesでの確認を推奨します。
- iPhone Safari / Android Chromeの**実機での音出し・ロック試験は未実施**です。下の手順で別々に確認してください。

### 実機チェック
1. 120 BPM・4/4でSTART。1分間で約120拍、4拍ごとに高い音が鳴ることを確認。
2. 再生中にBPMを60へ変更。間隔が約1秒になることを確認。
3. STOP直後にクリックが止まることを確認。
4. 3/4、6/8、アクセントOFF、2〜4分割、ミュートと音量をそれぞれ確認。
5. 再読み込みして設定が復元されることを確認。
6. ホーム画面から起動し同様に確認。オンラインで一度開いた後、機内モードで再起動して表示を確認。
7. 通常再生とは別に、再生中にロック・アプリ切り替えを実施。停止し、戻った画面でSTARTから再開できることを確認。

WebKit背景音声の参考：https://bugs.webkit.org/show_bug.cgi?id=220879 （過去の実装報告。現在の全端末の動作を保証するものではありません）

## 改良用の構成
- dist/index.html：画面
- dist/style.css：スマホ優先のスタイル
- dist/app.js：操作・設定保存・音声予約・振り子
- dist/manifest.webmanifest：PWA設定
- dist/sw.js：オフライン保存。更新時はCACHEのバージョンも上げます。
- dist/icons/：ホーム画面用PNGアイコン

依存ライブラリやサーバー処理がなく、このソースをそのまま改良できます。

## デザイン更新 v2
明るいグレーに水色・ミント・黄橙色を配色。重りは72×60 CSS pxの操作領域で、30〜300 BPMと位置を双方向に同期します。重りを選択してキーボードの上下キーでも操作できます。

更新版の確認：ドラッグ方向、30〜300の上下限、位置同期、ドラッグ中の中央固定、再生状態の維持、離した後の振り再開は模擬DOMの動作テストで確認。今回のブラウザ接続は安全ポリシーで拒否されたため、更新後の画面・実機のドラッグと音声連続性は未確認です。

## 拍子・アクセント更新 v3
通常画面の拍子をタップすると4列×3行の一覧を表示します。1/4、2/4、3/4、4/4、5/4、6/4、3/8、5/8、6/8、7/8、9/8、12/8から選択できます。選択中は黄橙色です。閉じるボタン、一覧の外側、Escapeでも閉じられます。
「音とリズムの設定」内の「1拍目のアクセント」でON/OFFを切り替えます。ONは小節の1拍目が1800Hz、通常の拍は1200Hz。OFFでは各拍は1200Hz・同じ音量です。細分化の補助クリックは従来通り低め・小さめです。再生中も変更でき、予約済みの音（最大約100ms）の後に反映されます。拍子とアクセントは自動保存・復元されます。
拍子の変更時は従来通り停止します。STARTで再開してください。BPMと重りの操作は継続して使えます。
模擬DOM・音声ノードのテストで全12拍子の2小節、アクセントON/OFF、再生状態の維持、設定復元と重り操作を確認済み。今回の一覧画面とスマホ実機のタップ・音出しは未確認です。
